# Облачные сессии и teleport

[← README](../../README.ru.md) · [English](../cloud.md)

Специальные облачные команды выбирают аккаунт через ту же безопасную границу
запуска, что и `run`, а самой облачной операцией управляет Claude Code.
Менеджер не вызывает Anthropic API, не читает credentials и не хранит состояние
облачных сессий или кредитов.

## Запуск новой облачной сессии

```bash
claude-acc cloud personal1 "Продолжи реализацию"
```

Claude запускается ровно с такими аргументами:

```text
--cloud
Продолжи реализацию
--permission-mode
auto
```

Задача остаётся сразу после `--cloud`. Команда всегда запрашивает режим Auto,
потому что предназначена для автономной работы в облаке. Upstream Claude
предоставляет Auto только тогда, когда это разрешено политикой организации
аккаунта и поддерживается выбранной моделью; `claude-acc` не пытается заранее
определить доступность. Облачные сессии предлагают Accept edits, Plan и Auto,
но не Bypass permissions. Дополнительные флаги вроде
`--dangerously-skip-permissions` отклоняются до запуска Claude. Чтобы выбрать
другой upstream-режим или передать другие продвинутые флаги Claude, используйте
прозрачный escape hatch:

```bash
claude-acc run personal1 --cloud "Спланируй эту миграцию" --permission-mode plan
```

Специальная команда создаёт только новые сессии по самой конструкции: она не
передаёт `-p`, который upstream Claude требует для отправки follow-up в
существующую сессию через `--cloud`. Поэтому даже точная строка `session_...`,
`cse_...` или `claude.ai/code/...` передаётся как описание задачи новой
сессии. R2 не добавляет отдельную manager-команду для follow-up.

### Аккаунт и доступность

Для именованного аккаунта cloud запускается с:

```text
CLAUDE_CONFIG_DIR=~/.claude-switch/accounts/<имя>
ANTHROPIC_CONFIG_DIR=~/.claude-switch/accounts/<имя>/.anthropic
```

Также действует полная очистка переменных аутентификации, провайдера и
маршрутизации, описанная в [Аккаунтах и конфигурации](accounts.md#безопасная-граница-запуска).
`default` сохраняет обычное upstream-поведение профилей Claude и Anthropic.

Облачные сессии требуют подходящего claude.ai-аккаунта и разрешающей политики
организации. Сейчас Claude Code предоставляет их поддерживаемым местам Pro,
Max, Team и Enterprise. Конфигурации Amazon Bedrock, Google Cloud Agent
Platform, Microsoft Foundry и других сторонних провайдеров upstream Claude
может отклонить. Менеджер не делает предварительную проверку: реальную ошибку
аккаунта или провайдера сообщает Claude.

### Какой репозиторий отправляется

Upstream Claude сам решает, как предоставить репозиторий облачной сессии.
Обычно он клонирует текущий GitHub remote и ветку, если настроенный доступ к
GitHub это позволяет. В других ситуациях, включая некоторые репозитории без
подходящего remote или установки GitHub App, Claude Code может собрать bundle
локального репозитория и загрузить его.

На нативном Windows такой bundle может включить незакоммиченные изменения
отслеживаемых файлов без исключений по чувствительным именам, которые
применяются на macOS, Linux и WSL. Перед осознанной отправкой локального bundle
проверьте или спрячьте через stash чувствительные незакоммиченные изменения
tracked-файлов. `claude-acc` не делает commit, stash, push и вообще не меняет
Git-состояние перед запуском cloud.

## Teleport облачной сессии

```bash
claude-acc teleport personal1 session_123
```

Запускаются точные аргументы:

```text
--teleport
session_123
```

Значение сессии передаётся без изменений под той же R1-изоляцией выбранного
аккаунта. Менеджер не ищет его в локальных транскриптах и не использует
`session copy` или `--resume`.

Claude сам проверяет, что терминал авторизован в том же claude.ai-аккаунте,
находится в правильном репозитории, имеет подходящее Git-состояние и может
получить облачную ветку. Он может предложить сделать stash, получить ветку и
переключить локальную ветку перед загрузкой облачного разговора. `--teleport`
— upstream-операция с облачной сессией, а не открытие локальной истории через
`--resume`.

## Что менеджер не учитывает

Менеджер не перечисляет облачные сессии, не отправляет follow-up сообщения,
не проверяет облачное использование и не вычисляет остаток cloud credits.
Состояние сессий и доступные лимиты смотрите в собственных интерфейсах Claude.
